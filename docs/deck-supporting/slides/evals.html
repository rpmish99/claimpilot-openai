Evals: threshold sweep and calibration

18 claims × 2 runs per setting

The threshold barely matters here: 0.70 to 0.95 give the same safety and about the same cost. Escalation is driven by poor scans, rule failures and would-be returns. I kept 0.90 as a default and don’t claim it is optimal.

Confidence decides when to look harder, never what is true: 43 confident errors in about 4,900 reads, so identity and provider fields are verified against FHIR in code.

From 0.70 to 0.95 safety is identical, cost is 0.77 to 0.88 cents and escalation stays at 56 to 58 percent, because rule failures, poor scans and would-be returns drive escalation, not the threshold. I kept 0.90 as a conventional default. The calibration chart shows why a threshold exists at all: below 0.90 reads are wrong far more often than stated; above it, 43 reads out of about 4,900 were still wrong, which code catches by checking FHIR. The same runs are published to the OpenAI Evals dashboard with string-check graders.
