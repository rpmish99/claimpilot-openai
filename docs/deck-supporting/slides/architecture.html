Where the OpenAI Platform fits

Every model call goes to OpenAI. The customer’s AWS account hosts the app and the data.

The customer’s hosting is drawn with the official AWS Architecture Icons. Editable source: docs/architecture/claimpilot-architecture.pptx

Supporting slide for questions about the deployment. This demo is about the OpenAI Platform: the Extraction Agent and the Resolution Agent are OpenAI Agents SDK objects, and every model call goes to the OpenAI Responses API (gpt-6-luna first, gpt-6.1-sol when code escalates). AWS is where the customer would host the app and keep its data. Walk the numbered steps: 1, claims arrive one at a time or as a batch drop in S3. 2, each S3 event becomes an SQS message; the queue absorbs bursts, retries, and dead-letters failures. 3, the supervisor Lambda runs both agents in-process and calls OpenAI; how many claims run in parallel is one configurable setting, sized against OpenAI rate limits and the account's Lambda quota. 4, rules in code, then the Resolution Agent does typed FHIR lookups and creates the Claim in HealthLake. 5, code decides; status, audit trail and atomic batch counters go to DynamoDB. 6, SNS sends processor and provider messages and one summary per batch. 7, processors review exceptions through Amplify, API Gateway and Lambda.
