The solution

Models read and match; code makes the decision

1 · EXTRACT

Extraction Agent

PDF scan → strict schema. gpt-6-luna reads; code escalates to gpt-6.1-sol when the scan is poor or a field is unsure

2 · VALIDATE

Rules in code

NPI check digit, ICD-10 and CPT format, dates, totals. Each rule has an ID and a route

3 · RESOLVE

Resolution Agent

5 typed FHIR tools on HealthLake: match member, coverage and providers, then create the Claim. Output guardrail

4 · DECIDE

Supervisor in code

Verifies unsure fields against FHIR, then routes: auto-accept, review or return

5 · HUMAN

Processor review

Exceptions arrive explained. One-click approve or return, with an editable provider message

Business rules live in code, so they are testable and auditable; the models can explain a rule finding but cannot overrule it.

Two agents, each with one job, run in a fixed order by ordinary code. The Extraction Agent is perception only: no tools, strict schema. The Resolution Agent uses five typed, least-privilege tools against HealthLake. The validators, the check against FHIR records, the guardrail and the final routing are code, so no prompt wording can talk a claim past a rule. No agent handoffs: the workflow is known ahead of time, so a model never chooses the next step. AWS hosts the app and the FHIR data; only the document and lookup results go to OpenAI, per call.
