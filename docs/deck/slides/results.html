Synthetic, edge-case-heavy set (58% escalated); 36 runs per row; also in OpenAI Evals. A pilot re-measures on 500+ real scans.

Start the 18-claim batch first: it lands in S3, each file becomes an SQS message, and Lambda works through them 6 at a time. That number is a setting, kept low on this demo account so the app stays responsive. One SNS summary arrives when the last claim lands. While it runs: the letter-O member ID is retried with a zero, confirmed by name and birth date, and logged as a correction. The phone photo escalates from gpt-6-luna to gpt-6.1-sol, and an unreadable billing NPI sends it to a processor. On the evals, 18 claims including a prompt-injection attempt and a duplicate, 36 runs per row: the fast model alone, the strong model alone and the cascade all had zero wrong auto-accepts and zero wrong returns, so this set can't rank them on safety. Cost differs: 0.09 cents, 1.09 cents and 0.88 cents per claim. I keep the cascade as insurance. In development the fast model alone once wrongly returned a correct claim, and a live batch caught it misreading a handwritten member ID at high confidence, which is why returns are now always confirmed by the strong model. With 36 clean runs I can only say the failure rate is below about 8%. The cascade costs about 0.8 cents more per claim, and breaks even if it prevents one wrongful return in roughly 400 to 900 claims, using CAQH's $3.15 to $7.35 to submit a claim again. The evals also found two bugs in my own rule checks, which I fixed and covered with tests.
